# 架构边界与当前状态

状态：有效 · 日期：2026-10-10 · 范围：已确认原则，未冻结生产设计 · 关联：ITER-001

当前没有业务运行时或完整新协议。不能把[选型研究](../research/robot-agent-eino-selection-2026-10-09.md)中的分层草案描述为已实现系统。

## 已确认原则

- 机器人 Agent 为核心，可接通用工具；完整保留[原功能](../requirements/README.md)。
- 模型、入口、场景和设备适配分开，避免厂商协议与部署位置固定业务逻辑。
- Gateway 主动出站连接；机器人在 NAT 后也能沿已建立连接收发命令和事件。
- 实际运动规划、执行约束和设备控制留在本地。
- 长任务具有进度、终态、取消与查询；断网或重启后先对账，结果未知不等于未执行。
- 一个任务具有明确负责人；设备、会话、任务、工具集合与事件必须隔离。
- 优先复用所选框架的 Agent、上下文、流程与恢复机制，不另建并行编排引擎。

## 尚未冻结

Eino 是优先原型候选，Mastra 为对照候选；具体版本、模型适配、持久化、Agent 首个部署位置和目标资源门槛需通过原型确定。工程目录约定不代表每个模块必须独立进程或微服务。

后续正式设计须明确逻辑模块、依赖、接口、数据流、失败和恢复、配置与验收；部署选择与模型位置分别说明。影响长期维护的决定进入[决策记录](../decisions/README.md)。

本轮只建立[目录边界](../standards/layout.md)与[编码规则](../standards/coding.md)，不预建未验证业务骨架。
