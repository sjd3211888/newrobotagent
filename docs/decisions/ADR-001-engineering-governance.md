# ADR-001：工程组织与开发流程

状态：有效 · 日期：2026-10-10 · 范围：整个重构仓库 · 关联：ITER-001

## 背景

新目录最初只有选型文档。原工程已有完整业务链路，但文档存在不同版本描述，工作区包含未提交改动和大量本地产物。此次需要统一代码、文档、开发和验收路径。

## 候选与决定

选择“规范文档 + 基础自动检查 + 设计和业务评审”。仅靠文档容易偏离；以全部指标硬性阻断会带来过多维护成本。文件行数和设计质量作为评审信号，格式、测试、本地链接与目录规则自动检查。

用户确认按场景小步闭环，而非先独立建设全部模块或集中实现整个系统。每轮有需求、设计、计划、可运行结果和验收记录；旧功能逐项对照。

用户确认在任务分支小步本地提交，不默认推送、合并或部署。采用单仓库，业务目录按职责组织，首次需要时创建。详细规则集中在[工程规范](../standards/README.md)。

## 影响与验证

人和 AI 使用同一流程。统一脚本通过公开命令检查基本约束；新语言检查随语言引入。以 ITER-001 的[验收记录](../reports/ITER-001-engineering-standards.md)验证规范可找到、模板可用、断链与错误放置可识别。

此次不决定生产框架、全部模块接口、部署位置或性能门槛。改变本决策时提交新 ADR 并链接替代关系。
