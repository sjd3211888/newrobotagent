# 文档规范

状态：有效 · 日期：2026-10-10 · 范围：全仓库 · 关联：ITER-001

## 分类与单一来源

根 README 描述目标和当前状态，`docs/README.md` 提供顺序导航。有效规则集中在 `docs/standards`；有效架构在 `docs/architecture`；需求与功能基线在 `docs/requirements`。

每轮记录分为 `docs/designs`、`docs/plans` 和 `docs/reports`；重要取舍在 `docs/decisions`；调研在 `docs/research`；部署、升级和排障在 `docs/operations`。模板在 `docs/templates`；被替代内容归入 `docs/archive` 并注明替代文件。

设计解释为什么及如何工作；计划描述实施顺序；报告记录实际结果。历史选型和历史计划不能覆盖当前有效设计。避免在多个文件复制同一条规范，改为链接。

## 编号与格式

- 中文正文、英文文件名、UTF-8、LF。路径使用相对链接，不写开发机绝对路径作为仓库链接。
- 正式说明标注状态、日期、适用范围和关联迭代；模板明确标注模板身份。
- 迭代依次编号 `ITER-001`，文件名为 `ITER-001-short-topic.md`，设计、计划、报告使用同名，编号不得复用。
- 功能使用 `FEAT-001`；验收场景在本轮使用 `ITER-001-CASE-01`。缺陷可以归入所属功能和迭代，不强制另建重复编号系统。
- 决策使用 `ADR-001-short-topic.md`。规范状态为草案、有效、已替代；迭代记录使用待确认、已确认、执行中、已完成或未通过。
- 日期默认按用户所在时区记录；运行证据需注明时区，跨机器事件优先携带 UTC 时间与关联编号。

模板填写时将示例和说明替换为真实内容，不保留未填写字段。暂未决定的设计明确列出问题和下一步，不能作为已确认实施依据。

## 链接与更新

新增正式文档必须从相应导航或当前迭代入口可达；代码变更同步更新受影响说明、接口契约和验收条件。本地文件链接由检查脚本校验，锚点与外部链接由评审确认。

从旧工程导入研究资料时保留来源、日期和验证状态。未导入的原工程文件用来源路径说明，不伪造仓库链接。技术版本是调研快照，不自动成为项目依赖。

已有实现与文档冲突时先核对源码、测试和运行环境，记录差异；不能仅因为文档日期较新就判断已部署。有效说明随实现更新；已验收历史记录通过补充勘误保留原结论。

## 最小内容

需求包含目标、范围、原行为和验收条件；设计包含边界、接口、数据流、失败处理和兼容性；计划包含具体任务与检查；验收包含环境、命令、结果、证据和限制。模板见[模板导航](../templates/README.md)。

修改规范时说明影响范围并同步机器检查或人工清单。过期文档明确链接替代文档；归档后更新导航，避免仍将其作为当前入口。
