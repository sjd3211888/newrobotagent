# 目录与模块边界

状态：有效 · 日期：2026-10-10 · 范围：全仓库 · 关联：ITER-001

## 根目录约定

| 路径 | 职责 |
| --- | --- |
| `README.md` | 项目目标、状态与顺序阅读入口 |
| `AGENTS.md` | AI 工作入口与强制约束 |
| `CONTRIBUTING.md` | 环境、开发命令和贡献流程 |
| `docs/` | 规范、需求、设计、计划、决策、验收和运维说明 |
| `cmd/` | Go 程序入口与依赖装配 |
| `internal/` | 内部业务模块和适配器 |
| `sdk/` | 对外 SDK，按语言组织 |
| `web/` | 前端工程和管理页面 |
| `protocols/` | 跨进程协议和 Schema 的源定义、版本及生成说明 |
| `configs/` | 示例配置、审定提示词；不含真实密钥和设备配置 |
| `scripts/` | 可复用、可重入的开发、检查和交付工具 |
| `tests/` | 跨模块集成、场景和 E2E 测试；工程工具测试在 `tests/tooling/` |
| `testdata/` | 可提交的小型脱敏样本及来源说明 |
| `.local/` | 本机配置、日志、缓存、实验和临时结果，忽略 |
| `build/` | 构建输出，忽略 |
| `dist/` | 交付产物，忽略；长期保存使用外部存储与校验清单 |

目录首次使用时建立。新增根目录先更新本规范和检查脚本的允许列表，不能绕过检查随意创建 `scratch`、`temp` 或重复的源码根。

## 代码依赖

- `cmd` 只能装配服务和处理进程生命周期，不承载业务状态机。
- `internal/<module>` 按业务职责组织；模块说明包含用途、公开接口、依赖和最小检查。
- 业务规则依赖其需要的接口；模型、数据库、设备协议和 Web 适配器实现这些接口。厂商 SDK 原始类型不进入业务接口。
- 接口在实际消费方定义，避免提前抽象所有组件。跨模块依赖须单向，无循环；业务模块不得依赖程序入口。
- Eino 相关装配和适配集中在 Agent 模块中。确有需要暴露框架类型时在设计说明理由，不让领域状态依赖厂商实现。
- SDK 公共 API 和跨进程协议在设计中单独审查。只有确有外部 Go 消费需求时才引入 `pkg/` 并记录决策。
- 协议源定义保持单一来源；生成文件旁标明生成工具、版本和命令，不手工修改生成代码。

## 配置、测试和资源

单元测试跟随源码；集成与场景测试位于 `tests`，样本在 `testdata`。Go 依赖 `go.mod/go.sum` 管理；前端引入时提交包元数据与锁文件。第三方源码仅在许可、体积与维护方式明确后引入，并记录来源。

可提交配置提供占位值和校验说明；真实配置进入 `.local` 或目标环境管理系统。小型审定知识样本可进入 `testdata`，生产知识和导览媒体使用版本、来源和外部存储清单管理。

临时实验先在 `.local` 中进行；成为长期工具时整理到 `scripts`，补参数、失败行为与验证。交付包不得反向成为源码来源。
