# 编码规范

状态：有效 · 日期：2026-10-10 · 范围：全仓库 · 关联：ITER-001

## 职责与接口

- 代码标识、路径和提交标题使用英文；设计和解释性注释可用中文。命名说明业务含义，避免无边界 `utils`。
- 文件保持单一职责，生产源码超过约 500 行触发评审；按变化原因和职责拆分，不按行数机械切割。
- 公开接口说明输入输出、错误、资源所有权、取消、超时和兼容性。接口应能通过模拟实现验证，但模拟不代替真实协议验收。
- 外部协议、领域对象和存储对象分别建模；类型转换发生在边界，禁止传递无约束大对象作为通用上下文。
- 只抽象实际需要的变化点。引入依赖、语言或生成工具时固定版本并记录理由、许可与目标平台。

## Go

使用 `gofmt`；包名简短小写。错误以 `%w` 保留原因，按需要使用 `errors.Is/As` 或明确错误类型；不吞错误、不靠错误文本驱动业务。预期失败返回 error，panic 仅用于不可恢复的程序错误。

需要取消的操作接收 `context.Context`，通常放在第一个参数；不将请求 context 保存为长期共享状态。goroutine、队列和订阅明确退出与关闭责任；共享状态有明确同步方式，队列有容量和满队列策略。

超时和重试按操作语义设定，记录配置来源。构造函数接收显式依赖；禁止全局可变模型会话或设备状态导致串用。

## 其他语言与工具

Python 工程脚本当前使用标准库，遵循 PEP 8；副作用入口放在 `main`，文件使用 UTF-8，执行外部命令用参数列表。检查命令返回明确退出码，不改写源码。

C++ 引入时固定标准版本、编译器和 clang-format 配置；使用 RAII，明确线程与回调生命周期。前端引入时固定 Node 和包管理器版本、提交锁文件，启用格式、lint、类型检查和必要测试。对应检查接入统一入口之前，不得宣称该语言代码满足工程完成标准。

跨平台脚本不依赖开发机绝对路径，不拼接未经正确处理的 shell 命令，不使用进程输出暴露密钥。

## 模型、任务和物理执行

- 模型适配与业务编排分离。提示词、工具定义和模型参数属于可影响行为的版本化资产。
- 设备身份、权限和目标绑定由可信入口注入，不能信任模型自报身份。
- 观测引用关联设备、采集时间、坐标系和有效期；动作使用可核对的任务与命令编号。
- 请求收到、任务受理、动作结束、业务目标验证和结果未知分别记录。未知结果先查询和对账，不能继承通用工作流重试而重复动作。
- 模型取消、播音停止和物理动作停止分别确认；本地执行约束与运动规划不被云端或模型绕过。

日志包含必要的设备、会话、话轮、任务和命令关联信息。密钥和私人内容不进入普通日志；完整交互证据使用单独访问控制与保留策略。性能优化先测量再修改，并保留同场景对照结果。
