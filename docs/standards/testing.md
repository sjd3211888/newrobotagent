# 测试与验收规范

状态：有效 · 日期：2026-10-10 · 范围：全仓库 · 关联：ITER-001

## 测试分层

| 层级 | 验证内容 | 位置与要求 |
| --- | --- | --- |
| 单元 | 业务规则、参数、状态、错误和取消 | 与源码同目录；Python 工具测试在 `tests/tooling` |
| 集成 | 模块、存储、模型或协议边界 | `tests`；区分模拟与真实依赖 |
| 场景/E2E | 从入口到输出或任务终态 | 关联功能和迭代验收条件 |
| 实机 | 真实采集、播放、观测与物理执行 | 明确硬件、版本、操作者及执行证据 |
| 性能/故障 | 延迟、吞吐、资源、取消与恢复 | 使用可重复输入和已说明故障条件 |

测试断言用户行为、状态契约和失败处理，避免只复述实现。低风险纯文档修改使用链接、差异和阅读检查，不强制增加无意义测试。修复缺陷时补覆盖失败条件的回归；并发、生命周期和去重改动增加针对性 race 检查。

## 统一基础检查

```sh
python scripts/check.py --scope all
```

检查不改写源码。`docs` 检查必需文件、根目录与产物放置、Markdown 本地文件引用；`code` 运行工程工具测试，在根目录存在 `go.mod` 时执行 Go 格式、`go vet ./...` 和 `go test -count=1 ./...`。检查按错误返回非零退出码。

没有 Go 源码时显示“不适用”，有 Go 源码但没有对应模块定义则失败。新增嵌套 Go 模块需同时扩展检查入口；未配置语言检查的源代码不能被默认为通过。C++ 与前端在首次引入时固定工具版本、命令和必要测试并接入检查。

文档检查验证本地文件目标，跳过 fenced code 和 inline code 中的示例，并支持行内和引用式 Markdown 链接。拒绝仓库外引用、`file:` 链接及指向本机/生成目录的引用。不请求网络 URL，不验证锚点。入口扫描包括已跟踪及未忽略的新文件；被跟踪的忽略目录仍须拦截。该检查不是完整密钥扫描器，提交前必须人工检查配置和差异。

## 机器人专项验收

至少按改动范围验证：新旧话轮隔离、音频打断、重复/迟到事件、身份与设备隔离、观测过期、长任务取消、断线及重启对账。物理动作未知时禁止盲目重试；工具受理或云端音频发送不等于动作成功或扬声器播放完成。

模型验证固定模型、提示词、工具版本和输入样本；不能只凭一次随机回答判断迁移完成。实机执行必须在明确授权和现场条件下进行，统一检查命令不触发动作。

## 证据与报告

报告写明提交/分支、系统、工具链、依赖、配置方式、实际命令、结果与限制。日志和媒体放在 `.local` 或受控外部存储，正式报告保留脱敏摘要、校验值与定位方式。

状态统一使用“通过”“未通过”“未运行”“不适用”，按本地、模拟、真实服务和实机分别记录。本地构建或测试不能证明云端已更新、模型密钥有效、数据库已迁移或设备服务可用。
