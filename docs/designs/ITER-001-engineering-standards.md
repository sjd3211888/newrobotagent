# ITER-001：工程规范设计

## 目标与结构

从根 README 可顺序找到功能基线、架构边界、工程规范、当前迭代和运维入口。规则集中维护，AI 与人使用同一套文件。原工程仅作参考，本轮不实现业务运行时。

采用单仓库，按职责保留代码目录约定，实际使用时创建。有效说明和历史记录分开；五类模板使每轮可追溯。已有选型文档保存原始 Git 基线后移入研究目录，原工程未导入文件改为来源路径说明。

## 检查接口

`python scripts/check.py --scope docs|code|all`，默认 all，退出 0 表示适用检查通过，非零表示失败。脚本只读检查，不格式化、不访问外部 URL、不连接设备。外部命令使用参数数组，返回失败不能隐去。

docs 范围检查必需文件、允许的根目录和产物放置、Markdown 本地文件链接。扫描 Git 已跟踪及未忽略新文件；已删除文件不检查内容。禁止引用仓库外路径。支持行内链接、图片、引用式链接和嵌套括号路径，忽略 fenced/inline code；外部 URL 与文档锚点不校验。文本以 UTF-8 读取。

code 范围运行 Python 工程工具回归。存在根 Go 模块时检查全部非生成 Go 源码格式，运行静态检查和单元测试；存在源码却缺少模块、嵌套模块或未配置语言检查时失败。没有业务代码时显示对应阶段不适用。新增语言在本轮设计和检查入口中扩展，不静默跳过。

## 失败与验证

错误包含文件和原因，检查失败返回非零。测试使用临时目录与模拟外部命令，验证断链、代码示例、引用式链接、UTF-8、仓库边界、错误根目录、被跟踪的忽略产物、Go 配置和命令失败。测试不触发模型或动作。

验收条件：入口链路可达、规范与模板覆盖已确认范围、检查识别坏链接与错误放置、原选型可追溯、没有敏感数据和产物进入 Git。人工评审模块边界、规则一致性和规范可执行性。性能、业务模型、实机和生产部署均不适用于本轮。
